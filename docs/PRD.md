## 1. 목표

> 출처: [PROPOSAL.md §2·§3](./PROPOSAL.md#3-목표와-성공-기준)

**업무 누락을 줄이고, 팀원별 업무 현황과 프로젝트 진행률을 한눈에 파악한다.**

팀이 프로젝트 단위로 업무를 등록하고 담당자·마감일·우선순위를 지정해 칸반 보드로 진행 상황을 관리하는 웹 서비스를 만든다. 차별화 기능은 **업무 변경 이력(Activity Log)**과 **마감 임박·지연 대시보드**다.

| 해결할 문제 | 해결 방안 |
| --- | --- |
| 업무 누락 | 업무 등록(담당자·마감일·우선순위), 칸반 보드 |
| 진행 상황 불투명 | 프로젝트 진행률, 최근 활동 20건 |
| 마감 놓침 | 마감 임박(3일 이내)·지연 업무 대시보드 |
| 변경 이유 불명 | 업무 변경 이력 자동 기록 |

## 4. 범위 밖 (Won't)

> 출처: [PROPOSAL.md §5 제외 범위](./PROPOSAL.md#제외-범위-만들지-않는-것) · [REQUIREMENTS.md §7.3](./REQUIREMENTS.md#73-wont--이번에-만들지-않음)

- 실시간 알림(WebSocket), 이메일 발송, 파일 첨부, 외부 서비스 연동
- LLM, RAG, LangChain, AI 에이전트, AI 모델 학습 등 AI 기능
- 보기 전용 역할(VIEWER) — 보류, 추후 재검토

새 기능 제안은 바로 구현하지 않고 REQUIREMENTS.md에 P2로 등록한 뒤 팀 검토로 결정한다.

## 5. 성공 기준

> 출처: [PROPOSAL.md §3](./PROPOSAL.md#3-목표와-성공-기준) — 확인 방법은 원본 참고

1. P0 기능 100% 구현 (수용 기준 점검)
2. P0 핵심 API(인증·권한·업무 CRUD) pytest 전부 통과
3. 권한 실패 케이스(비멤버 403 등)를 테스트로 보장
4. P1 우선 6개(프로젝트 진행률, 검색·필터, 댓글, 변경 이력 조회, 마감 임박·지연, 내 업무 대시보드) 구현
5. `main` 직접 push 0건, 모든 PR이 리뷰 1명 승인·린트 통과 후 병합
6. 명세와 구현 일치(명세에 없는 API·테이블 0개)
7. 데스크톱 브라우저에서 주요 화면 7개(로그인·회원가입, 프로젝트 목록, 칸반 보드, 업무 상세, 프로젝트 설정, 통계, 내 대시보드) 동작
8. 공통 모듈을 스타터킷으로 분리
