# 요구사항 명세서 (REQUIREMENTS.md)

> 프로젝트: 팀 협업 프로젝트 관리 시스템 (가칭 **TeamBoard**)
> 기간: 92시간 | 방식: SDD(Spec-Driven Development) | 버전: v0.3 (MVP 빈틈 보완: 내 정보 조회·멤버 목록·제거·이력 기록 P0)

## 1. 프로젝트 개요

팀이 프로젝트 단위로 업무(Task)를 등록하고, 담당자·마감일·우선순위를 지정해 진행 상황을 칸반 보드로 관리하는 웹 서비스입니다.

- **목표:** 업무 누락을 줄이고, 팀원별 업무 현황과 프로젝트 진행률을 한눈에 파악한다.
- **차별화 기능:** 업무 변경 이력(Activity Log)과 마감 임박·지연 업무 대시보드.
- **기술 스택:** React + Tailwind CSS / FastAPI + Pydantic / MariaDB + SQLAlchemy + Alembic / JWT
- **제외 범위:** 실시간 알림(WebSocket), 이메일 발송, 파일 첨부, 외부 서비스 연동, LLM, RAG, LangChain, AI 에이전트, AI 모델 학습 등 AI 기능

## 2. 사용자 역할

권한은 **시스템 역할**과 **프로젝트 내 역할** 두 단계로 나눕니다.

| 구분 | 역할 | 설명 |
| --- | --- | --- |
| 시스템 | `ADMIN` | 전체 사용자·프로젝트 조회, 계정 비활성화 |
| 시스템 | `USER` | 일반 사용자. 프로젝트를 만들면 그 프로젝트의 OWNER가 됨 |
| 프로젝트 | `OWNER` | 프로젝트 수정·삭제, 멤버 초대·제거, 역할 변경 |
| 프로젝트 | `MEMBER` | 업무 등록·수정, 상태 변경, 댓글 작성 |

> 보기 전용 역할(VIEWER)은 현재 범위에서 제외했고, 추후 다시 검토합니다. (CONSTITUTION.md 6-3)

## 3. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = 권장, **P2** = 시간이 남으면

### 3.1 인증·계정 (AUTH)

| ID | 요구사항 | 우선순위 |
| --- | --- | :-: |
| AUTH-01 | 이메일·비밀번호·이름으로 회원가입한다. 이메일은 중복될 수 없다. | P0 |
| AUTH-02 | 로그인 시 JWT Access Token을 발급한다. | P0 |
| AUTH-03 | 비밀번호는 bcrypt로 해시하여 저장한다. | P0 |
| AUTH-04 | 토큰으로 내 정보(이름·이메일)를 조회한다. 새로고침 시 로그인 상태 복원에 사용한다. | P0 |
| AUTH-05 | Refresh Token으로 Access Token을 재발급한다. | P2 |
| AUTH-06 | 내 이름을 수정한다. | P1 |

### 3.2 프로젝트 (PRJ)

| ID | 요구사항 | 우선순위 |
| --- | --- | :-: |
| PRJ-01 | 프로젝트를 생성한다(이름, 설명, 시작일, 종료일). 생성자는 OWNER가 된다. | P0 |
| PRJ-02 | 내가 속한 프로젝트 목록을 진행률과 함께 조회한다. | P0 |
| PRJ-03 | OWNER는 프로젝트를 수정·삭제할 수 있다. 삭제 시 하위 업무도 함께 삭제된다. | P0 |
| PRJ-04 | OWNER는 이메일로 기존 회원을 멤버로 추가하고 역할을 지정한다. | P0 |
| PRJ-05 | OWNER는 멤버를 제거한다. OWNER는 최소 1명 유지되어야 하고, 제거된 멤버가 담당하던 업무는 담당자 미지정이 된다. | P0 |
| PRJ-06 | 프로젝트를 보관(archive) 처리하여 목록에서 숨길 수 있다. | P2 |
| PRJ-07 | 프로젝트 멤버는 프로젝트 상세(이름·설명·기간)와 멤버 목록(이름·이메일·역할)을 조회한다. | P0 |
| PRJ-08 | OWNER는 멤버의 역할을 변경한다. OWNER는 최소 1명 유지되어야 한다. | P1 |

### 3.3 업무 (TASK)

| ID | 요구사항 | 우선순위 |
| --- | --- | :-: |
| TASK-01 | 업무를 등록한다(제목, 설명, 담당자, 마감일, 우선순위). | P0 |
| TASK-02 | 업무 상태는 `TODO` → `IN_PROGRESS` → `DONE`이며, 어느 방향으로든 변경할 수 있다. | P0 |
| TASK-03 | 담당자는 해당 프로젝트의 멤버(OWNER·MEMBER)만 지정할 수 있다. | P0 |
| TASK-04 | 우선순위는 `LOW`, `MEDIUM`, `HIGH`, `URGENT` 중 하나다. | P0 |
| TASK-05 | 칸반 보드에서 상태별 컬럼으로 업무를 조회한다. 상태 변경은 버튼(드롭다운)으로 한다. 컬럼 안의 카드는 우선순위 높은 순, 같으면 마감일 빠른 순(마감일 없음은 뒤)으로 정렬한다. | P0 |
| TASK-06 | 업무 상세에서 모든 항목을 수정·삭제한다. 삭제 전 확인 창을 띄운다. | P0 |
| TASK-07 | 제목 키워드, 담당자, 상태, 우선순위, 마감일 범위로 검색·필터링한다. | P1 |
| TASK-08 | 칸반 보드에서 드래그 앤 드롭으로 상태를 변경한다. | P2 |

### 3.4 댓글 (CMT)

| ID | 요구사항 | 우선순위 |
| --- | --- | :-: |
| CMT-01 | 업무에 댓글을 작성·조회한다. | P1 |
| CMT-02 | 본인 댓글만 수정·삭제한다. | P1 |

### 3.5 변경 이력 (LOG) — 차별화 기능

기록(LOG-01·02)은 업무 변경과 같은 트랜잭션에서 처리하므로 P0에 포함하고, 조회 화면(LOG-03)은 P1입니다.

| ID | 요구사항 | 우선순위 |
| --- | --- | :-: |
| LOG-01 | 업무의 생성, 상태·담당자·마감일·우선순위 변경, 삭제를 이력으로 자동 기록한다. | P0 |
| LOG-02 | 이력에는 변경자, 변경 항목, 이전 값, 새 값, 변경 시각이 남는다. | P0 |
| LOG-03 | 업무 상세에서 해당 업무의 이력을, 프로젝트 화면에서 최근 이력 20건을 조회한다. | P1 |

### 3.6 대시보드 (DASH)

| ID | 요구사항 | 우선순위 |
| --- | --- | :-: |
| DASH-01 | 프로젝트 진행률 = DONE 업무 수 / 전체 업무 수 (업무가 없으면 0%). | P0 |
| DASH-02 | 담당자별 상태별 업무 수를 표로 보여준다. | P1 |
| DASH-03 | **마감 임박**(3일 이내, 미완료)과 **지연**(마감일 경과, 미완료) 업무 목록을 보여준다. | P1 |
| DASH-04 | 내 대시보드: 나에게 할당된 업무를 프로젝트 구분 없이 마감일 순으로 보여준다. | P1 |

## 4. 비기능 요구사항

| ID | 구분 | 요구사항 |
| --- | --- | --- |
| NFR-01 | 보안 | 인증이 필요한 모든 API는 JWT를 검증하고, 프로젝트 API는 멤버십과 역할을 서버에서 확인한다. 프론트에서 버튼을 숨기는 것만으로 권한을 처리하지 않는다. |
| NFR-02 | 보안 | 비밀번호, 토큰 시크릿은 코드에 넣지 않고 `.env`로 관리한다. |
| NFR-03 | 검증 | 모든 요청은 Pydantic으로 검증하고, 실패 시 422와 필드별 오류 메시지를 반환한다. |
| NFR-04 | 오류 처리 | 오류 응답은 `{ "code": "...", "message": "..." }` 형식으로 통일한다. |
| NFR-05 | 성능 | 목록 API는 페이지네이션(기본 20건)을 지원한다. |
| NFR-06 | UI | 데스크톱 기준, 브라우저 창 크기에 맞춰 레이아웃이 조정되는 반응형 화면. |
| NFR-07 | 재사용 | 인증, API 클라이언트, DB 세션, 예외 처리, 공통 UI 컴포넌트는 별도 모듈로 분리해 스타터킷으로 재사용할 수 있게 한다. |
| NFR-08 | 테스트 | 인증·권한·업무 CRUD의 핵심 API는 pytest로 검증한다. |
| NFR-09 | 화면 처리 | 로그인하지 않은 사용자가 보호된 주소에 들어오면 로그인 화면으로 보낸다. 권한 없음(403)과 없는 주소(404)는 안내 화면을 보여 준다. |

## 5. 수용 기준 (예시)

**AUTH-01 회원가입**
- 주어진 상황: 이미 가입된 이메일이 있을 때
- 동작: 같은 이메일로 가입을 요청하면
- 결과: 409와 `EMAIL_ALREADY_EXISTS` 오류를 반환한다.

**TASK-03 담당자 지정**
- 주어진 상황: 사용자 B가 프로젝트 P의 멤버가 아닐 때
- 동작: P의 업무 담당자를 B로 지정하면
- 결과: 400과 `ASSIGNEE_NOT_MEMBER` 오류를 반환한다.

**NFR-01 권한**
- 주어진 상황: 사용자 A가 프로젝트 P의 멤버가 아닐 때
- 동작: A가 `GET /projects/{P}/tasks`를 호출하면
- 결과: 403과 `NOT_PROJECT_MEMBER` 오류를 반환한다.

**PRJ-05·PRJ-08 OWNER 유지**
- 주어진 상황: 프로젝트에 OWNER가 1명뿐일 때
- 동작: 그 OWNER의 역할을 MEMBER로 바꾸거나 제거하면
- 결과: 400과 `LAST_OWNER` 오류를 반환한다.

**LOG-01 변경 이력**
- 동작: 업무 상태를 TODO에서 IN_PROGRESS로 바꾸면
- 결과: `field=status, old=TODO, new=IN_PROGRESS`, 변경자, 시각이 이력에 1건 추가된다.

## 7. MVP 범위 요약

- **P0 (먼저 완성):** 인증(내 정보 조회 포함), 프로젝트 CRUD, 멤버 추가·목록·제거, 업무 CRUD, 칸반(버튼 방식, 정렬 기준), 진행률, 변경 이력 기록, 화면 접근 처리(로그인 이동·403·404)
- **P1 (그다음):** 검색·필터, 댓글, 변경 이력 조회, 마감 임박·지연 대시보드, 담당자별 현황, 내 정보 수정, 멤버 역할 변경
- **P2 (여유 있을 때):** 드래그 앤 드롭, Refresh Token, 프로젝트 보관, 관리자 기능
