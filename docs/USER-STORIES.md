## 작성 규칙

- 형식: **"(역할)로서, (목표)를 하고 싶다. 그래야 (이유)."**
- 각 스토리는 `REQUIREMENTS.md`의 기능 ID와 연결되고, 우선순위(P0/P1/P2)도 그대로 따릅니다.
- 수용 기준은 **주어진 상황 / 동작 / 결과** 형식으로 씁니다. 이 기준이 그대로 pytest·화면 테스트 시나리오가 됩니다.
- 크기는 상대 점수(1, 2, 3, 5, 8)로 추정합니다. 1점은 반나절 이하, 8점은 이틀 이상이며, 8점 이상은 나눠야 합니다.

## E1. 계정과 인증

### US-01. 회원가입 `AUTH-01, AUTH-03` · P0 · 2점
**방문자로서**, 아이디와 비밀번호로 가입하고 싶다. **그래야** 팀 프로젝트에 참여할 수 있다.

- 상황: 처음 방문한 사용자 / 동작: 아이디(영문 소문자·숫자 4~20자), 비밀번호(8~64자), 이름을 입력하고 가입 / 결과: 201과 함께 계정이 생성되고 로그인 화면으로 이동한다.
- 상황: 이미 가입된 아이디 / 동작: 같은 아이디로 가입(대소문자만 달라도 같은 아이디로 봄) / 결과: 409 `LOGIN_ID_ALREADY_EXISTS`, 화면에 "이미 사용 중인 아이디입니다" 표시.
- 상황: 형식이 틀린 아이디(한글·특수문자·길이 위반)나 짧은 비밀번호 / 동작: 가입 / 결과: 422, 해당 입력칸 아래에 오류 표시.
- DB에는 비밀번호가 bcrypt 해시로만 저장된다.

### US-02. 로그인 `AUTH-02` · P0 · 2점
**가입한 사용자로서**, 로그인하고 싶다. **그래야** 내 프로젝트와 업무를 볼 수 있다.

- 상황: 올바른 아이디·비밀번호 / 동작: 로그인 / 결과: Access Token을 받고 `/`로 이동한다. P0 기간에는 `/`가 프로젝트 목록(`/projects`)으로 이동하고, 내 대시보드(US-23)가 완성되면 대시보드를 보여 준다.
- 상황: 틀린 비밀번호 또는 없는 아이디 / 동작: 로그인 / 결과: 401 `INVALID_CREDENTIALS`. 어느 쪽이 틀렸는지는 알려주지 않는다.
- 상황: 비활성화된 계정 / 동작: 로그인 / 결과: 403 `ACCOUNT_DISABLED`.

### US-03. 로그인 유지와 로그아웃 `AUTH-02, AUTH-04, NFR-09` · P0 · 2점
**로그인한 사용자로서**, 새로고침해도 로그인이 유지되고, 원할 때 로그아웃하고 싶다. **그래야** 작업이 끊기지 않고, 공용 PC에서도 안전하게 마칠 수 있다.

- 상황: 로그인 상태 / 동작: 새로고침 / 결과: 저장된 토큰으로 내 정보를 조회해 로그인 상태가 복원되고, 화면 상단에 내 이름이 보인다.
- 상황: 로그인하지 않은 상태 / 동작: 보호된 주소로 직접 접속 / 결과: 로그인 화면으로 이동한다.
- 상황: 멤버가 아닌 프로젝트나 없는 주소로 접속 / 결과: 권한 없음(403) 또는 없는 페이지(404) 안내 화면이 보인다.
- 상황: 토큰 만료 / 동작: API 호출 / 결과: 401을 받으면 로그인 화면으로 이동한다.
- 동작: 로그아웃 / 결과: 저장된 토큰이 지워지고 로그인 화면으로 이동한다.

### US-04. 내 정보 수정 `AUTH-06` · P1 · 2점
**사용자로서**, 내 이름을 바꾸고 싶다. **그래야** 팀원이 나를 알아볼 수 있다.

- 동작: 이름을 수정 / 결과: 업무 담당자, 댓글 작성자 표시에 바뀐 이름이 보인다.

### US-31. 비밀번호 변경 `AUTH-07` · P2 · 2점
**사용자로서**, 비밀번호를 바꾸고 싶다. **그래야** 비밀번호가 노출됐을 때 계정을 지킬 수 있다.

- 동작: 현재 비밀번호와 새 비밀번호(8~64자) 입력 / 결과: 바뀌고, 다음 로그인부터 새 비밀번호를 쓴다.
- 상황: 현재 비밀번호가 틀림 / 결과: 400 `WRONG_PASSWORD`, "현재 비밀번호가 올바르지 않습니다".
- 상황: 새 비밀번호가 8자 미만이거나 64자 초과 / 결과: 422.

### US-32. 회원 탈퇴 `AUTH-08` · P2 · 3점
**사용자로서**, 더 이상 쓰지 않는 계정을 없애고 싶다. **그래야** 쓰지 않는 계정이 남아 도용되는 일을 막을 수 있다.

- 동작: 비밀번호를 다시 입력하고 탈퇴 / 결과: 로그아웃되고, 이후 그 아이디로 로그인할 수 없다(401 `INVALID_CREDENTIALS`).
- 결과: 모든 프로젝트에서 빠지고, 담당하던 업무는 담당자 미지정이 된다(업무마다 이력 기록).
- 결과: 내가 만든 업무, 댓글, 변경 이력은 남고 작성자는 "탈퇴한 사용자"로 보인다.
- 상황: 내가 마지막 OWNER인 프로젝트가 있음 / 결과: 400 `LAST_OWNER`, "OWNER를 넘기거나 프로젝트를 삭제한 뒤 탈퇴할 수 있습니다".
- 상황: 비밀번호가 틀림 / 결과: 400 `WRONG_PASSWORD`.
- 상황: 같은 아이디로 새로 가입 / 결과: 409 `LOGIN_ID_ALREADY_EXISTS`(아이디 재사용 불가).

## E2. 프로젝트와 멤버

### US-05. 프로젝트 만들기 `PRJ-01` · P0 · 2점
**팀장 지수로서**, 프로젝트를 만들고 싶다. **그래야** 팀 업무를 한곳에 모을 수 있다.

- 동작: 이름(필수), 설명, 시작일, 종료일을 입력하고 생성 / 결과: 프로젝트가 생기고 지수는 자동으로 `OWNER`가 된다.
- 상황: 종료일이 시작일보다 빠름 / 결과: 422, "종료일은 시작일 이후여야 합니다".
- 상황: 이름이 비어 있거나 30자 초과 / 결과: 422, "프로젝트 이름은 1~30자로 입력해 주세요". 입력칸은 30자까지만 입력되고 남은 글자 수가 보인다. 수정(US-08)에도 같은 규칙.

### US-06. 내 프로젝트 목록 보기 `PRJ-02` · P0 · 2점
**팀원 민호로서**, 내가 속한 프로젝트를 한눈에 보고 싶다. **그래야** 어디부터 볼지 정할 수 있다.

- 결과: 내가 멤버인 프로젝트만 카드로 보이고, 카드마다 이름, 기간, 내 역할이 표시된다. 진행률은 US-20(P1)에서 추가한다.
- 상황: 속한 프로젝트가 없음 / 결과: "프로젝트를 만들어 보세요" 안내와 생성 버튼.

### US-07. 팀원 초대하기 `PRJ-04` · P0 · 3점
**팀장 지수로서**, 팀원을 아이디로 추가하고 역할을 정하고 싶다. **그래야** 함께 업무를 관리할 수 있다.

- 동작: 가입된 아이디와 역할(OWNER/MEMBER)을 입력해 추가 / 결과: 상대방의 프로젝트 목록에 바로 나타난다.
- 상황: 가입하지 않은 아이디 / 결과: 404 `USER_NOT_FOUND`.
- 상황: 이미 멤버인 사람 / 결과: 409 `ALREADY_MEMBER`.
- 상황: MEMBER인 민호가 초대 시도 / 결과: 403 `FORBIDDEN`. 화면에서는 초대 버튼이 보이지 않는다.
- 결과: 설정 화면에서 멤버 목록(이름, 아이디, 역할)이 보인다. 멤버 목록은 OWNER·MEMBER 모두 볼 수 있다(`PRJ-07`). 업무 담당자 선택지도 이 목록을 쓴다.

### US-08. 프로젝트 수정·삭제 `PRJ-03` · P0 · 2점
**팀장 지수로서**, 프로젝트 정보를 고치거나 끝난 프로젝트를 지우고 싶다. **그래야** 팀이 늘 정확한 정보를 보고 목록이 정리된다.

- 동작: 이름, 설명, 기간 수정 / 결과: 바로 반영된다.
- 동작: 삭제 / 결과: 확인 창에서 프로젝트 이름을 입력해야 삭제되고, 하위 업무·댓글도 함께 삭제된다.
- 상황: MEMBER가 수정·삭제 시도 / 결과: 403.

### US-09. 멤버 제거 `PRJ-05` · P0 · 2점
**팀장 지수로서**, 잘못 추가했거나 팀을 떠난 사람을 프로젝트에서 빼고 싶다. **그래야** 관계없는 사람이 프로젝트 정보를 볼 수 없다.

- 동작: 설정 화면에서 멤버 제거 / 결과: 상대방의 프로젝트 목록에서 사라지고, 이후 이 프로젝트 API 호출 시 403.
- 상황: OWNER가 지수 1명뿐 / 동작: 지수 자신을 제거 / 결과: 400 `LAST_OWNER`.
- 상황: 제거된 멤버가 담당하던 업무 / 결과: 담당자가 비어 있는 상태(미지정)가 된다.
- 상황: MEMBER가 제거 시도 / 결과: 403.

### US-26. 멤버 역할 변경 `PRJ-08` · P1 · 1점
**팀장 지수로서**, 팀원의 역할을 바꾸고 싶다. **그래야** 관리 권한을 나누거나 내가 빠질 때 넘길 수 있다.

- 동작: 민호를 OWNER로 변경 / 결과: 민호도 멤버 관리와 프로젝트 수정을 할 수 있다.
- 상황: OWNER가 지수 1명뿐 / 동작: 지수 자신을 MEMBER로 변경 / 결과: 400 `LAST_OWNER`.

### US-10. 프로젝트 보관 `PRJ-06` · P2 · 1점
**팀장 지수로서**, 끝난 프로젝트를 지우지 않고 숨기고 싶다. **그래야** 기록은 남기면서 목록은 깔끔하게 유지할 수 있다.

- 동작: 보관 / 결과: 목록에서 사라지고 "보관된 프로젝트" 필터에서만 보인다. 보관된 프로젝트는 읽기 전용이다.

### US-33. 프로젝트 나가기 `PRJ-09` · P2 · 2점
**팀원 서연으로서**, 더 이상 참여하지 않는 프로젝트에서 스스로 나가고 싶다. **그래야** 내 목록이 정리된다.

- 동작: 설정 화면에서 "프로젝트 나가기" / 결과: 확인 창 후 내 목록에서 사라지고, 이후 그 프로젝트 API 호출 시 403.
- 결과: 내가 담당하던 업무는 담당자 미지정이 되고 업무마다 이력이 남는다(US-09와 같은 처리).
- 상황: 내가 마지막 OWNER / 결과: 400 `LAST_OWNER`.

## E3. 업무와 칸반

### US-11. 업무 등록 `TASK-01, TASK-03, TASK-04` · P0 · 3점
**팀원 민호로서**, 해야 할 일을 업무로 등록하고 싶다. **그래야** 잊지 않고 팀이 알 수 있다.

- 동작: 제목(필수), 설명, 담당자, 마감일, 우선순위를 입력 / 결과: `TODO` 컬럼에 정렬 기준(US-12)에 맞는 자리로 추가된다. 우선순위 기본값은 `MEDIUM`.
- 상황: 제목이 비어 있거나 30자 초과 / 결과: 422, "업무 제목은 1~30자로 입력해 주세요". 수정(US-14)에도 같은 규칙.
- 상황: 담당자 목록 / 결과: 이 프로젝트의 OWNER·MEMBER만 선택지에 나온다.
- 상황: API로 멤버가 아닌 사람을 담당자로 지정 / 결과: 400 `ASSIGNEE_NOT_MEMBER`.
- 상황: 마감일을 오늘 이전 날짜로 입력 / 결과: 등록된다(바로 "지연"으로 표시). 프로젝트 기간 밖의 날짜도 허용한다.
- 상황: 프로젝트 멤버가 아닌 사용자 / 결과: 프로젝트에 접근할 수 없고, API 호출 시 403 `NOT_PROJECT_MEMBER`.

### US-12. 칸반 보드 보기 `TASK-05` · P0 · 3점
**팀원 민호로서**, 업무를 상태별 컬럼으로 보고 싶다. **그래야** 전체 흐름을 한눈에 볼 수 있다.

- 결과: `할 일 / 진행 중 / 완료` 3개 컬럼, 각 카드에 제목, 담당자, 마감일, 우선순위 배지가 보인다.
- 결과: 마감일이 지난 미완료 카드는 빨간색, 3일 이내는 주황색으로 표시된다.
- 결과: 컬럼 안의 카드는 우선순위 높은 순(`URGENT` → `LOW`), 같으면 마감일 빠른 순이며, 마감일이 없는 카드는 뒤에 온다.
- 결과: 보드 상단에 프로젝트 이름, 기간이 보인다. 진행률은 US-20(P1)에서 추가한다.

### US-13. 업무 상태 바꾸기 `TASK-02, TASK-05` · P0 · 3점
**팀원 민호로서**, 업무를 시작하거나 끝내면 상태를 바꾸고 싶다. **그래야** 팀이 진행 상황을 안다.

- 동작: 카드의 상태 드롭다운에서 `진행 중` 선택 / 결과: 카드가 해당 컬럼으로 이동한다(US-20 이후에는 진행률도 다시 계산된다).
- 상황: `DONE`으로 변경 / 결과: `completed_at`이 기록된다. 다시 다른 상태로 바꾸면 비워진다.
- 결과: 변경할 때마다 `task_activities`에 이력이 1건 남는다(US-18과 같은 트랜잭션).
- 상황: 민호(MEMBER)가 작성자는 아니지만 담당자인 업무 / 동작: 상태 변경 / 결과: 성공.
- 상황: 서연(MEMBER)이 작성자도 담당자도 아닌 업무 / 동작: 상태 변경 / 결과: 403 `FORBIDDEN`. 화면에서는 상태 드롭다운이 비활성화된다.

### US-14. 업무 상세 보기·수정·삭제 `TASK-06` · P0 · 3점
**팀원 민호로서**, 업무 내용을 자세히 보고 고치고 싶다. **그래야** 업무 정보가 늘 최신 상태로 유지된다.

- 동작: 카드 클릭 / 결과: 상세 모달이 열리고 URL이 `/projects/:id/tasks/:taskId`로 바뀐다(새로고침해도 유지).
- 동작: 항목 수정 후 저장 / 결과: 보드에 바로 반영된다.
- 동작: 삭제 / 결과: "이 업무를 삭제할까요?" 확인 창에서 확인해야 삭제된다.
- 상황: MEMBER가 남이 만든 업무를 수정 또는 삭제 / 결과: 403 `FORBIDDEN`. OWNER는 모든 업무를 수정·삭제할 수 있다.
- 상황: MEMBER가 남이 만들고 본인이 담당자인 업무를 수정 / 결과: 상태만 바꿀 수 있고, 다른 항목(제목·설명·담당자·마감일·우선순위)을 바꾸면 403. 화면에서는 상태 외 입력칸이 읽기 전용이다.

### US-15. 업무 검색·필터 `TASK-07` · P1 · 3점
**팀장 지수로서**, 조건으로 업무를 걸러 보고 싶다. **그래야** 이번 주에 급한 일만 골라 볼 수 있다.

- 동작: 제목 키워드, 담당자, 상태, 우선순위, 마감일 범위 중 원하는 조건을 조합 / 결과: 조건에 맞는 카드만 보인다.
- 결과: 필터 조건이 URL 쿼리에 남아서 링크를 공유하면 같은 화면이 보인다.
- 동작: "필터 초기화" / 결과: 전체 업무가 다시 보인다.

### US-16. 드래그 앤 드롭으로 상태 변경 `TASK-08` · P2 · 5점
**팀원 민호로서**, 카드를 끌어다 다른 컬럼에 놓아 상태를 바꾸고 싶다. **그래야** 드롭다운을 열지 않고 빠르게 상태를 바꿀 수 있다.

- 동작: 카드를 다른 컬럼으로 드래그 / 결과: US-13과 같은 API로 상태가 바뀌고 `position`이 저장된다.
- 상황: API 실패 / 결과: 카드가 원래 자리로 돌아가고 오류 메시지가 뜬다.

### US-28. 업무 체크리스트(todo) `TASK-09` · P2 · 3점
**팀원 민호로서**, 업무 하나를 끝내기 위해 해야 할 일을 잘게 나눠 적고 체크하고 싶다. **그래야** 어디까지 했는지 잊지 않는다.

- 동작: 업무 상세에서 항목 추가(1~100자) / 결과: 목록 맨 아래에 미완료 상태로 추가된다.
- 상황: 이미 항목이 10개 / 동작: 추가 / 결과: 400 `CHECKLIST_LIMIT_EXCEEDED`, "체크리스트는 업무당 10개까지입니다". 화면에서는 추가 버튼이 비활성화된다.
- 동작: 항목 체크·체크 해제, 내용 수정, 삭제 / 결과: 바로 반영된다.
- 상황: 프로젝트 멤버가 아닌 사용자가 API 호출 / 결과: 403 `NOT_PROJECT_MEMBER`.
- 권한: 항목 추가·수정·체크·삭제는 OWNER, 업무 작성자, 업무 담당자만 할 수 있다. 다른 MEMBER는 보기만 가능(403 `FORBIDDEN`).
- 상황: 업무 삭제 / 결과: 체크리스트 항목도 함께 삭제된다.

### US-29. 업무 진행률 보기 `TASK-10` · P2 · 1점
**팀장 지수로서**, 업무마다 얼마나 진행됐는지 보고 싶다. **그래야** 진행 중인 업무 중 막힌 것을 찾을 수 있다.

- 결과: 업무 진행률 = 체크된 항목 수 / 전체 항목 수. 카드와 업무 상세에 "2/5 (40%)"처럼 보인다.
- 상황: 체크리스트 항목이 없음 / 결과: 진행률을 표시하지 않는다.
- 업무 상태(`TODO`/`IN_PROGRESS`/`DONE`)는 진행률에 따라 자동으로 바뀌지 않는다.

### US-30. 달력으로 업무 보기 `TASK-11` · P2 · 3점
**팀원 서연으로서**, 업무 마감일을 달력으로 보고 싶다. **그래야** 이번 달 일정이 어떻게 몰려 있는지 알 수 있다.

- 결과: `/projects/:id/calendar`에서 월간 달력의 마감일 칸에 업무 제목과 우선순위 배지가 보인다. 이전·다음 달로 이동할 수 있다.
- 동작: 업무 클릭 / 결과: 업무 상세 모달이 열린다.
- 상황: 마감일이 없는 업무 / 결과: 달력에 나오지 않는다.

## E4. 소통과 이력

### US-17. 업무에 댓글 달기 `CMT-01, CMT-02` · P1 · 3점
**팀원 민호로서**, 업무에 질문이나 진행 메모를 남기고 싶다. **그래야** 메신저를 뒤지지 않아도 된다.

- 동작: 업무 상세에서 댓글 작성 / 결과: 작성자, 시각과 함께 시간순으로 보인다.
- 동작: 내 댓글 수정·삭제 / 결과: 반영된다. 남의 댓글에는 수정·삭제 버튼이 없고 API는 403.
- 상황: 빈 댓글 또는 300자 초과 / 결과: 422. 입력칸에 남은 글자 수가 보인다.

### US-18. 업무 변경 이력 기록 `LOG-01, LOG-02` · P0 · 2점
**팀장 지수로서**, 업무가 바뀔 때마다 누가 언제 무엇을 바꿨는지 자동으로 남기고 싶다. **그래야** 나중에 이력 화면이 생겼을 때 처음부터의 기록을 볼 수 있다.

- 상황: 민호가 마감일을 11/20에서 11/25로 변경 / 결과: `task_activities`에 변경자 민호, `field=due_date`, 이전 값, 새 값, 시각이 1건 남는다.
- 상황: 한 번에 상태와 담당자를 함께 변경 / 결과: 이력이 항목별로 2건 남는다.
- 상황: 업무가 삭제됨 / 결과: `DELETED` 이력이 남고, 업무가 지워져도 이력은 사라지지 않는다(`task_id` NULL).
- 상황: 이력 기록이 실패 / 결과: 업무 변경도 함께 취소된다(같은 트랜잭션).

### US-27. 업무 변경 이력 보기 `LOG-03` · P1 · 2점
**팀장 지수로서**, 누가 언제 무엇을 바꿨는지 보고 싶다. **그래야** 마감일이 왜 바뀌었는지 확인할 수 있다.

- 결과: 업무 상세 이력 탭에 "민호 · 마감일 11/20 → 11/25 · 방금 전"처럼 최신순으로 보인다.
- 상황: 업무가 삭제됨 / 결과: 프로젝트의 최근 이력에는 "삭제됨" 기록이 남아 있다.

### US-19. 프로젝트 최근 활동 보기 `LOG-03` · P1 · 2점
**팀원 서연으로서**, 프로젝트에서 최근에 무슨 일이 있었는지 보고 싶다. **그래야** 회의 없이 상황을 파악할 수 있다.

- 결과: 프로젝트 통계 화면에서 최근 이력 20건이 최신순으로 보이고, 항목을 누르면 해당 업무 상세가 열린다.

## E5. 현황과 대시보드

### US-20. 프로젝트 진행률 보기 `DASH-01` · P1 · 1점
**팀장 지수로서**, 프로젝트가 얼마나 진행됐는지 숫자로 보고 싶다. **그래야** 회의 없이 일정이 늦어지는지 판단할 수 있다.

- 결과: 진행률 = 완료 업무 수 / 전체 업무 수. 업무가 없으면 0%. 칸반 상단과 프로젝트 카드에 표시된다.

### US-21. 담당자별 업무 현황 `DASH-02` · P1 · 3점
**팀장 지수로서**, 팀원별로 업무가 몇 개씩 있는지 보고 싶다. **그래야** 한 사람에게 일이 몰리지 않게 나눌 수 있다.

- 결과: 통계 화면에서 담당자 × 상태(할 일/진행 중/완료) 표가 보이고, 담당자 미지정 업무도 따로 집계된다.

### US-22. 마감 임박·지연 업무 보기 `DASH-03` · P1 · 3점
**팀장 지수로서**, 마감이 다가오거나 이미 늦은 업무를 따로 보고 싶다. **그래야** 놓치기 전에 챙길 수 있다.

- 결과: "지연"(마감일이 어제 이전, 미완료)과 "임박"(마감일이 오늘 ~ 오늘+3일, 미완료) 두 목록이 마감일 순으로 보인다.
- 상황: 마감일이 오늘인 미완료 업무 / 결과: "임박"에 나온다.
- 상황: 완료된 업무나 마감일이 없는 업무 / 결과: 목록에 나오지 않는다.

### US-23. 내 업무 대시보드 `DASH-04` · P1 · 2점
**팀원 민호로서**, 로그인하면 내 업무부터 보고 싶다. **그래야** 여러 프로젝트를 돌아다니지 않아도 된다.

- 결과: `/`에서 나에게 할당된 미완료 업무가 프로젝트 이름과 함께 마감일 순으로 보이고, 지연·임박 업무는 맨 위에 강조된다.

## E6. 시스템 관리

### US-24. 사용자 관리 `ADM-01` · P2 · 3점
**관리자로서**, 전체 사용자를 보고 문제가 있는 계정을 막고 싶다. **그래야** 악용되는 계정으로부터 서비스를 지킬 수 있다.

- 동작: 계정 비활성화 / 결과: 그 사용자는 로그인할 수 없다(US-02의 403).
- 상황: 일반 사용자가 관리자 API 호출 / 결과: 403.

### US-25. 토큰 자동 재발급 `AUTH-05` · P2 · 1점
**사용자로서**, 작업 중에 갑자기 로그아웃되지 않았으면 좋겠다. **그래야** 입력하던 내용을 잃지 않고 계속 작업할 수 있다.

- 상황: Access Token 만료 / 결과: Refresh Token으로 자동 재발급되어 하던 작업이 이어진다.
