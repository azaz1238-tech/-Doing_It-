### 결정
- F0-05 받는 방법(제안): 최진영이 기능 브랜치로 올리고 PR → 김서현 리뷰·승인 → `main` 병합 → `main`을 pull 받아 `feat/TASK-05-kanban` 생성. 남의 브랜치에서 바로 갈라지지 않는다(병합 때 꼬임 방지).
- 문구 따옴표는 코드와 같게 `'…'`로 통일(Figma에 있던 `‘…’` 교체).
- 조사가 틀릴 수 있는 문구는 조사를 고정된 단어에 붙인다.
  - 업무 삭제: `'{업무 제목}' 업무가 삭제됩니다` (최진영 수정안 그대로)
  - 프로젝트 삭제: `'{프로젝트 이름}'을` → `프로젝트 이름({이름})을`로 제안 (예: `'백엔드 MVP'을`이 틀림). 최진영 확인 필요.
- 상태 변경 토스트(T-F2-11)는 상태별 조사를 표로 고정해서 쓴다: `'할 일'로` / `'진행 중'으로` / `'완료'로`.
- 스켈레톤 막대 색: 시안의 `neutral-100 #EEF1F5`는 흰 카드 위에서 안 보임 → `neutral-200 #E2E7EE` 제안.

### 결정
- 담당자 선택지는 멤버 목록 API(`listMembers`)를 쓴다. 상세 모달은 현재 담당자가 목록에 없으면(멤버에서 빠짐) 그 사람도 선택지에 넣어 값이 보이게 한다.
- 상세 삭제 확인 문구는 SPEC TASK-06-c 그대로 "이 업무를 삭제할까요?". 11/16 말투 규칙(`~하시겠습니까?`)과 다름 → 맞추려면 SPEC 수정 필요(팀 확인 대기).
- S8 안내 화면 문구는 시안 기준으로 통일하고 UI-DESIGN S8 표에 적음: 403 "프로젝트 OWNER에게 멤버 추가를 요청해 주세요", 404 "주소가 바뀌었거나 삭제된 항목입니다", 제목 위 `403`·`404`.
- 글자 수는 서버(Python `len`)와 같게 코드 포인트로 센다. 최진영 #58로 `core/utils/text.js` `countChars` 하나로 합쳐짐.
- 빠른 두 번 클릭은 상태(`useState`)가 아니라 `useRef`로 막는다(등록·삭제).
- 리뷰 요청 온 PR은 직접 테스트한 뒤 문제없으면 승인·merge까지 한다. 명세 변경(SPEC-CHANGELOG) PR은 팀장 확인 뒤 병합, `core/` PR은 같은 영역(최진영 ↔ 김서현) 리뷰를 채운다.

### 문제와 해결
- **AUTH-04-c:** 주소를 직접 연 화면에서 로그아웃 → 뒤로 가기 → 로그인된 칸반이 다시 보임(브라우저 bfcache). 앱 안 이동만으로는 재현 안 됨 → 이슈 #35, 최진영 #38(`pageshow` 처리)로 해결.
- **두 번 클릭 중복 등록:** 등록 버튼·Enter를 빠르게 두 번 → 업무 2개. 프로젝트 생성 모달도 같음(#48) → `useRef`로 해결.
- **이모지 제목:** 😀 16개를 서버는 받는데 화면은 32자로 세서 막음 → 코드 포인트로 셈(#50), 입력칸 숫자 표시는 #58.
- **main ESLint 실패:** PR 각각은 통과했는데 #36·#37이 함께 병합되며 `Placeholder`가 안 쓰이게 됨 → #40(최진영 #41도 같은 수정, 충돌 없이 합쳐짐).
- **#37이 `core/` 변경인데 같은 영역 리뷰 없이 병합:** S8 문구 차이가 그대로 남았음 → #61 리뷰어로 최진영을 넣어 사후 확인, 아이콘은 #63.
- **#61 충돌:** 최진영 #60(UI-DESIGN v1.5·SPEC-CHANGELOG #17)이 먼저 병합 → 버전 줄·변경 이력 맨 위가 충돌. 미리 v1.6·#18로 번호를 비워 둬서 둘 다 살려 해결.
- **verify.md 편집 실수:** 정규식 치환에서 요약 칸에 제어 문자(`\x01`)가 들어감 → 바로 복구 커밋.
- **Figma:** MCP 호출 한도(Starter)로 읽기 1번 뒤 막힘 → 직접 수정 불가. 문구는 문서·코드로 맞추고, S2 성공 토스트는 Figma에 없음(코드·UI-DESIGN에만 있음)을 확인.
