### 결정
- F0-05 받는 방법(제안): 최진영이 기능 브랜치로 올리고 PR → 김서현 리뷰·승인 → `main` 병합 → `main`을 pull 받아 `feat/TASK-05-kanban` 생성. 남의 브랜치에서 바로 갈라지지 않는다(병합 때 꼬임 방지).
- 문구 따옴표는 코드와 같게 `'…'`로 통일(Figma에 있던 `‘…’` 교체).
- 조사가 틀릴 수 있는 문구는 조사를 고정된 단어에 붙인다.
  - 업무 삭제: `'{업무 제목}' 업무가 삭제됩니다` (최진영 수정안 그대로)
  - 프로젝트 삭제: `'{프로젝트 이름}'을` → `프로젝트 이름({이름})을`로 제안 (예: `'백엔드 MVP'을`이 틀림). 최진영 확인 필요.
- 상태 변경 토스트(T-F2-11)는 상태별 조사를 표로 고정해서 쓴다: `'할 일'로` / `'진행 중'으로` / `'완료'로`.
- 스켈레톤 막대 색: 시안의 `neutral-100 #EEF1F5`는 흰 카드 위에서 안 보임 → `neutral-200 #E2E7EE` 제안.

### 결정
- 검색·필터 조건은 URL 쿼리에만 둔다. 이름은 API 쿼리와 같은 `q`·`assignee_id`(`none` = 담당자 없음)·`priority`·`due_from`·`due_to`. 상태 필터는 따로 두지 않음(칸반 컬럼이 곧 상태).
- 프로젝트·멤버는 처음 한 번만, 컬럼은 필터가 바뀔 때마다 다시 부르도록 effect를 나눔.
- 필터를 연달아 바꿔도 앞 조건이 사라지지 않게 항상 지금 주소(`window.location.search`) 기준으로 계산.
- 검색칸은 초기화할 때만 새로 그린다(`resetKey`). 초기화하면 반영 대기 중인 검색어도 취소.
- 진행률(#85)과 BoardPage 충돌을 피하려고 최진영 변경을 먼저 병합하고 그 위에서 시작.
- 통합 이슈는 결함·문서 불일치·운영 작업으로 나누고, 이미 계획에 있는 것은 이슈 없이 보고서에만 남김.

### 문제와 해결
- **필터 조건이 API 요청에 안 붙음:** 화면·주소는 맞았는데 `listTasks`가 `status`·`page`·`size`만 넘기고 나머지를 버림 → 받은 조건을 그대로 넘기도록 수정. 네트워크 요청을 직접 찍어 보고 발견.
- **검색하다 멈췄다가 이어 치면 글자가 사라짐 (#86 리뷰, 서승범 지적):** 검색칸 `key={filters.q}` 때문에 0.3초 뒤 입력칸이 새로 만들어져 커서가 빠짐. 내 확인 스크립트가 값을 한 번에 넣어서 못 잡았음 → `resetKey`로 바꾸고, 이번엔 한 글자씩 입력해 확인.
- **고치다 찾은 것:** 초기화 순간 주소 갱신이 한 박자 늦어 새 검색칸에 옛 검색어가 다시 채워짐 → 초기화로 새로 그릴 때는 빈 칸으로 시작.
- **F3 확인 스크립트 실수:** 설정 화면에서 멤버 추가 칸 대신 위쪽 프로젝트 정보 폼에 값을 넣어 테스트 프로젝트 이름이 바뀜 → 그 프로젝트는 지우고, 추가 칸을 정확히 집어 다시 확인.
- **진행률 막대 갱신이 안 된 것처럼 보임:** 첫 확인에서 상세 삭제 뒤 "2/4"로 남음 → 네트워크 기록으로 두 가지 방법(카드 클릭·주소로 열기)을 재현하니 둘 다 0.5초 안에 갱신. 첫 결과는 스크립트 타이밍 문제로 판단.
- **문서 차이 발견:** 멤버 중복 문구가 SPEC "이미 프로젝트 멤버입니다"(코드) vs UI-DESIGN S7 "이미 멤버입니다" → 이슈 #75.

### 결정
- 이름 수정 모달과 API 호출은 `core/`에 둔다. TopBar가 `core/`에 있고 `core/`는 `features/`를 import하지 않으므로, `/users/me`를 이미 다루는 AuthContext에 `updateName`을 둠.
- 이름을 바꾸면 화면을 새로 그려 서버에서 다시 받는다(`<Outlet key={user.name}>`). 화면마다 갱신 코드를 넣는 대신 한 곳에서 처리 — 필터·열린 업무는 주소에 있어 유지된다.
- 불러오기 실패는 403·404(안내 화면)와 그 밖(500·네트워크 → `다시 시도`)을 나눈다. 컬럼 첫 실패는 컬럼 안 안내, 이미 카드가 있으면 카드를 두고 토스트만.
- 담당자별 현황의 0건 멤버는 API를 바꾸지 않고 화면이 멤버 목록으로 채운다(팀장 결정).
- verify.md는 원래 "각자 고치지 않기"였지만 7절에 "결과 칸은 김서현이 채운다"고 되어 있어, 팀장을 리뷰어로 넣고 PR로 반영(승인됨).
- 명세에 없던 문구는 코드에만 두지 않고 UI-DESIGN·SPEC-CHANGELOG로 올림(CLAUDE.md §7).

### 문제와 해결
- **백엔드 API 전에 이름 수정 확인:** `PATCH /users/me`가 405 → 실패 토스트·모달 유지는 실제로, 성공 흐름은 브라우저 요청 가로채기로 응답을 흉내 내 확인. API 병합 뒤 실제 저장으로 다시 확인.
- **이름을 바꿔도 보던 화면은 옛 이름:** 처음 확인은 화면을 새로 열어서 해 놓쳤음. 점검 중 코드를 읽다 발견 → 칸반·상세·설정·통계에서 바꿔 보며 확인.
- **검색어 `|` 버그:** 필터 조건을 `|`로 이어 붙였다 나눠 `a|b`가 `q=a`·`assignee_id=b`로 나감 → `URLSearchParams`로 묶고 `|`·`&`·`=`·`%` 검색 확인.
- **모바일 "담당자 없음" 잘림:** 고정 폭만 풀면 375px는 되지만 360px에서 13px 모자람 → 글자 폭을 재 보고 모바일 아바타 숨김. 320px는 표 최소 너비로 상자 안 가로 스크롤.
- **확인 스크립트 실수:** 검증 화면 텍스트를 줄바꿈 이스케이프 실수로 못 읽거나, 이미 다른 화면으로 이동한 뒤 값을 읽어 "없음"으로 나옴 → 셀렉터·순서를 고쳐 다시 확인(코드 문제 아님).

### 결정
- 매뉴얼 스크린샷은 시드 데이터가 아니라 매뉴얼 전용 데이터(지연·임박·완료가 고루 보이게)로 따로 찍음. 실제 시연은 seed.py 데이터.
- 발표 자료는 각자 .pptx 파일로 만들고 팀장이 합침(최진영 분담: 01~07 최진영, 08~16 김서현, 17 마무리). 슬라이드 번호는 자동 번호가 아니라 직접 쓴 글자라 순서가 바뀌면 손으로 고침.
- 발표 자료 숫자는 결과서 값만 씀(수용 75/75, pytest 464, 보안 점검 64, 브라우저 14화면).

### 문제와 해결
- **발표 자료 크기 다름:** 처음엔 13.33인치(와이드)로 만들어 최진영 파일(10×5.625)과 안 맞음 → 비율만 줄이니 글자가 넘쳐 전체를 다시 배치. 슬라이드 9장을 그림으로 뽑아 넘침·한 글자 줄바꿈 확인 후 2곳 수정(08 카드 제목, 11 "차별화" 위치).
- **자동 슬라이드 번호와 제목 번호가 겹침:** 진영님 기준이 제목 줄 번호라 자동 번호를 뺌.
- **간트 #149를 처음에 놓친 이유:** 막대 위치를 1280px에서만 쟀음 → 회고 "다음에 바꿀 것"에 여러 폭 측정을 넣음.
