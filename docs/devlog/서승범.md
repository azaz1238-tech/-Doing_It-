### 결정
- 삭제된 업무의 `/tasks/{id}/activities`는 404 `TASK_NOT_FOUND`(업무가 없음). 삭제된 업무 이력은 프로젝트 최근 활동에서만 보임.
- 이력 조회 서비스는 `task_service.get_task`를 쓰지 않고 직접 조회 + `require_project_role` (task_service가 activity_service를 import해 순환이 생김).
- 담당자 이력의 사용자는 `users[...]`로 바로 꺼냄. 사용자는 명세상 지우지 않으므로 `.get`으로 감싸 "담당자 없음"으로 잘못 보이게 하지 않음.
- 404 문구 중복은 2곳뿐이라 공통화하지 않음(세 번 반복될 때 공통화 규칙).
- 쿼리 수 테스트: SQLAlchemy `before_cursor_execute`로 행 2개일 때와 20개일 때 SQL 수가 같은지 확인 → D9-03 쿼리 최적화 기록 재료.

### 문제와 해결
- `dict(db.execute(...))`가 `'ChunkedIteratorResult' object is not subscriptable` 오류 → Result에 `keys()`가 있어 매핑으로 오해됨. 행을 풀어서 dict로 만듦.
- 코드를 일부러 망가뜨린 뒤 `git checkout -- backend/app`으로 되돌리다가 커밋 안 한 조회 코드까지 사라짐 → 다시 작성해 통과 확인. 이후 망가뜨리기 전에 먼저 커밋하기로 함.
- 명세 제안 브랜치를 만들 때 팀장이 #19·API-SPEC v1.5를 먼저 씀 → main에서 다시 만들어 #20·v1.6으로 올림.
