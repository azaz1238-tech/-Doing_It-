### 결정
- **멤버 추가 검사 순서:** 경로의 프로젝트 404 → 403 → 본문 `login_id` 404. 권한 없는 사람이 아이디 존재 여부를 알아낼 수 없게 한다(SPEC-CHANGELOG #14).
- **멤버 제거 대상이 멤버가 아니면** 404 `MEMBER_NOT_FOUND` "해당 사용자는 이 프로젝트의 멤버가 아닙니다"(SPEC-CHANGELOG #16). P0에서는 MEMBER의 제거 요청을 모두 403으로 막는다(본인 나가기는 P2 PRJ-09).
- **잠그는 순서 고정:** OWNER 행 → 대상 멤버 행 → 대상의 업무 행(DATABASE-DESIGN §6.1). 대상 행은 `FOR UPDATE`로 최신 값을 읽는다(REPEATABLE READ 스냅숏 문제).
- **제거 로직은 `_remove_member_rows`(커밋 안 함)로 분리** — 탈퇴(AUTH-08)에서 프로젝트별로 다시 쓴다.
- `_ER_DUP_ENTRY = 1062`가 두 번째 등장(auth_service·member_service). 세 번째 나오면 공통화한다.
- "초안 만들어줘"는 파일을 만들지 않고 예시 코드만 보여 주는 것으로 작업 방식을 정함.

### 문제와 해결
- `uvicorn --reload`가 새 DELETE 경로를 반영하지 않아 Postman이 404 → 서버 재시작.
- Windows에서 Python `write_text`가 CRLF로 저장 → LF로 바꿔 저장.

### 결정
- 시연은 로컬 대신 **배포 주소**로 함. 배포 DB에만 오늘 날짜 기준 시연 데이터를 넣고, 내 대시보드 달력은 더 채우지 않음(지연을 늘리면 오히려 일정 관리를 못 하는 것처럼 보임 → 12월로 넘겨 보여 줌).
- Railway Pre-deploy는 `python -m alembic -c backend/alembic.ini upgrade head`만. seed는 첫 배포 때 한 번만 실행하고 명령에서 뺌(데이터가 있으면 seed가 멈추기도 함).
- 로고 색 변경은 동결 뒤 UI 변경이지만 색만 바뀌고 UI-DESIGN에 색 규칙이 없어 SPEC-CHANGELOG #41만 기록.
- `v1.0`은 로고 변경까지 들어간 main에 붙임. KPT·최종 보고서는 문서라 태그 뒤에 병합해도 됨.

### 문제와 해결
- **배포 서버 로그인 500(`Table 'railway.users' doesn't exist`):** 마이그레이션을 안 돌림 → Pre-deploy에 alembic 추가.
- **Pre-deploy 실패(`No 'script_location' key found`):** Pre-deploy는 셸을 거치지 않아 `cd backend &&`가 안 먹음 → `-c backend/alembic.ini`로 설정 파일 위치를 직접 줌.
- **병합 뒤에도 `/login`·`/api/health` 404:** Netlify가 404를 캐시 → 주소 뒤에 쿼리를 붙여 200 확인, 잠시 뒤 정상.
- **추가 데이터 스크립트 422:** 멤버 추가 본문에 `role` 필수 → 반쯤 만들어진 프로젝트를 지우고 고쳐서 다시 실행. 끝 출력만 cp949로 깨졌고 데이터는 정상.
- **DB를 MySQL로 잘못 적음:** Railway DB 이름만 보고 짐작 → MariaDB로 고침.
- **KPT 커밋이 병합된 `fix/D12-logo-color`에 들어감:** `docs/D12-02-kpt`가 예전에 쓴 이름이라 새 브랜치를 못 만들었는데 명령이 이어서 실행됨 → 푸시 전에 `docs/D12-02-kpt-retro`로 옮기고 원래 브랜치는 되돌림.
