### 결정
- `get_current_user`는 `core/auth.py`가 아니라 `app/services/auth_service.py`에 둔다. `core/`는 `app/`의 `User`를 import할 수 없기 때문(스타터킷 규칙). `core/auth.py`는 토큰 검사만 한다 (ARCHITECTURE v1.3, SPEC-CHANGELOG #4). 구현은 T-F1-03.
- `.env` 형식을 ARCHITECTURE §6 키로 새로 맞춤(값은 무작위 생성, 기존 파일은 `.env.bak`로 백업).
- 회원가입 중복 검사는 미리 SELECT하지 않고 DB UNIQUE(오류 1062)에 맡긴다 → 동시에 가입해도 한 명만 성공.
- `system_role` 등 정의되지 않은 필드는 `extra="forbid"`로 422 → 가입 요청으로 ADMIN이 되는 것을 막음.
- 422 오류 문구는 **임시**. 프론트 화면 자료가 나오면 확정한다.
- 로그인(T-F1-02)은 아이디의 공백 제거·소문자 변환만 하고, 형식이 틀린 아이디도 422가 아니라 **401 `INVALID_CREDENTIALS`** 로 통일한다. 비활성 계정 403 `ACCOUNT_DISABLED`는 명세대로 둔다. → API-SPEC §5.1에 한 줄 추가 필요.
- 이번 한 번만 main에 직접 푸시(문서 통일, T-F0-04·08). 원래 규칙은 브랜치 + PR.

### 결정
- **로그인 시간차 공격 방지:** 없는 아이디도 더미 해시로 bcrypt 비교를 한 번 해서 응답 시간으로 계정 존재를 알 수 없게 한다.
- **로그인 검사 순서:** 아이디 없음 401 → 비밀번호 틀림 401 → 비활성 403. 비밀번호가 틀리면 비활성 여부를 알려 주지 않는다.
- **프로젝트 기간 검사는 두 군데:** 본문에 두 날짜가 다 있으면 스키마에서 422(404·403보다 먼저). `end_date`만 보내면 저장될 최종 값으로 서비스에서 비교하고, 같은 422 형식(`errors[0].field = end_date`)으로 던진다.
- **`my_role`은 모델에 없어서** 서비스가 `(Project, 역할)` 짝을 돌려주고 응답은 `ProjectOut.of()`로 만든다.
- **프로젝트 삭제는 `projects` 행만 지운다.** 멤버·업무·이력은 DB `ON DELETE CASCADE`에 맡긴다(모델에 ORM 관계 없음).
- **Postman은 영역별 파일:** 한 파일을 둘이 고치면 JSON 충돌이 나므로 `F1-auth`·`F2-projects`·`F2-tasks`… 로 나눈다. 실행할 때마다 새 아이디로 가입해 몇 번을 돌려도 된다.

### 문제와 해결
- Docker Desktop이 꺼져 있어 pytest가 `OperationalError` → Docker 실행 후 `docker compose up -d`.
- 프로젝트 생성 테스트에서 `NoResultFound`: 테스트 세션이 `user.id`를 읽을 때 REPEATABLE READ 스냅숏을 열어 API가 넣은 행이 안 보임 → API 호출 후 DB를 볼 때 `db.rollback()` 먼저.
- Git Bash `curl`이 한글 본문을 UTF-8로 안 보내 400 → 본문을 UTF-8 파일로 저장해 `--data-binary @파일`로 전송.
  - 이때 발견: 404 외 HTTP 오류(본문 파싱 실패 등)는 FastAPI 기본 `detail` 형식으로 나간다 → `core/exceptions.py` 보완 필요(아래 내일).
- 동기화 중 SPEC-CHANGELOG에서 내 승인 수정(#11)과 새로 들어온 #12 줄이 충돌 → 둘 다 남기고 해결.
- Postman CLI가 저장소에 `.postman/`(개인 작업공간 ID)을 만듦 → 커밋하지 않음.
