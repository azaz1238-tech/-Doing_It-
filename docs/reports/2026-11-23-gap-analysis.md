### 5.3 영향 분석 누락 — Postman 컬렉션 (11/23 발견·수정)
- 설명 필수(#21)로 프로젝트 생성 API가 설명 없는 요청을 422로 거절하게 됐는데, **Postman 컬렉션 `F2-tasks`·`F3-members`는 이름만으로 프로젝트를 만들어** 첫 요청부터 실패했다(검증 51개 실패). pytest는 팩토리를 함께 고쳐 통과했기 때문에 놓쳤다.
- 두 컬렉션 본문에 설명을 넣어 고쳤고, 4개 컬렉션 모두 통과(요청 105개, 검증 106개 실패 0)를 확인했다.
- **교훈:** API 입력 규칙을 바꾸면 pytest뿐 아니라 Postman 컬렉션·시드(`seed.py`)·화면도 함께 확인한다. PR 템플릿(§7 #78)의 리뷰 체크에 반영한다.

## 9. 결론

P0은 명세와 구현 사이에 갭이 없다. P1 1순위 6개는 API·화면 모두 끝났다. 오늘 안에 이슈 수정 PR을 병합하고 F5·댓글 화면 검증을 마치면 11/24 수용 기준 85개 검증으로 넘어갈 수 있다. 2순위 3개는 동결 규칙에 따라 오늘 끝나지 않으면 범위에서 빼는 것을 권한다. 이번 분석에서 찾은 가장 큰 절차상 약점은 **명세 변경의 영향 범위를 pytest만으로 확인한 것**(§5.3)이며, PR 템플릿 체크 항목으로 보완한다.
