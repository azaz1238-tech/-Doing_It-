## 3. AI 활용 사례
### 3.1 잘된 예
- **간트 (TASK-12, #140 → #143)**
  - 상황: 기능 동결일에 기능 ID도 없는 간트를 추가해야 함.
  - AI에게 준 것: 먼저 명세 초안(REQUIREMENTS·SPEC 시나리오 a~c·UI-DESIGN 간트 절)을 쓰게 하고, 리뷰 반영 뒤 "UI-DESIGN 간트 절 + TASK-12-a~c대로 구현, 기존 `getDueInfo`·`date.js` 재사용"으로 구현.
  - 결과와 근거: 명세 리뷰에서 서승범이 `created_at` UTC 자르기 함정을 짚어 구현 전에 반영. 구현은 업무 6개 막대의 시작·끝을 날짜 칸과 px 단위로 대조해 확인, 최진영·서승범 승인 후 병합(#143). 색 기준은 `getDueInfo`에 `tone`을 더해 보드와 하나로 맞춤.
- **A조 수용 검증 35개 (D10-01, #134)**
  - 상황: 하루 안에 다른 조 기능 35개를 화면까지 확인해야 함.
  - AI에게 준 것: SPEC §11 시나리오 원문, "화면은 실제 클릭·입력, 거절 시나리오는 API로도, 비활성 계정·만료 토큰은 DB·같은 키로 준비".
  - 결과와 근거: 35개 모두 ✅, 화면 문구·버튼 상태·API 코드를 한 번에 기록(#134). 이후 D10-04 브라우저 점검(Chrome·Edge × 5폭 × 14화면, #135)도 같은 방식으로 재사용.

### 3.2 AI가 틀렸거나 명세와 달랐던 예
- **검색칸 입력 중 글자 사라짐 (#86)**
  - AI가 만든 것: 필터를 주소와 맞추려고 검색칸에 `key={filters.q}`를 줘서, 0.3초 뒤 입력칸이 새로 만들어지며 커서가 빠짐.
  - 어떻게 발견했나: 코드 리뷰(서승범). AI의 확인 스크립트는 값을 한 번에 넣어 이 상황을 만들지 못함.
  - 고친 방법: 초기화할 때만 새로 그리는 `resetKey`로 바꾸고, 한 글자씩 입력하는 확인으로 다시 검증.
- **간트 좁은 창에서 막대·오늘 선 어긋남 (#149 → #160)**
  - AI가 만든 것: 날짜 머리줄은 최소 672px인데 막대 줄은 더 좁아질 수 있는 레이아웃.
  - 어떻게 발견했나: 최진영이 간트를 확인하다 발견(이슈 #149). AI의 첫 확인은 막대 위치를 1280px에서만 재고, 좁은 폭은 가로 스크롤만 봄.
  - 고친 방법: 표 최소 폭을 "업무 칸 + 672px"로 잡고, 9가지 폭에서 머리줄·막대 줄 폭과 위치 차이를 px로 재서 확인(#160). 명세 변경 없음.

## 4. 명세가 AI 결과에 준 영향
- **명세가 자세했던 부분:** UI-DESIGN의 문구·권한별 화면 상태표(S6)·마감 표시 규칙(§6.3)은 AI가 그대로 옮겨 수용 검증에서도 문구까지 바로 대조할 수 있었다. 숫자 규칙(제목 1~30자, 임박 오늘~+3일)도 화면·서버가 같은 값을 써서 어긋나지 않았다.
- **명세가 비어 있던 부분에서 AI가 정한 것:**
  - 이름 수정 모달 부제·토스트, "업무를 불러오지 못했습니다 + 다시 시도" → 임시로 정한 뒤 팀장 확인을 받아 UI-DESIGN에 올림(#129, SPEC-CHANGELOG #29).
  - 담당자별 현황에서 업무 0건 멤버 표시 여부 → AI가 정하지 않고 팀장 결정으로 넘김(#127, UI-DESIGN §9 #5).
  - 드래그 앤 드롭의 권한 없는 카드(TASK-08-b): 구현(끌 수 없음)이 명세(끌어 놓으면 문구)와 달라 확인 중 발견 → 팀장이 명세를 고침(#133, SPEC-CHANGELOG #30).

## 5. 다음에 바꿀 것
- **화면 명세에 "실패·빈 상태·문구" 칸을 먼저 채운다.** 이번에 나중에 명세로 올린 것(#129)이 모두 이 칸이었다.
- **확인 스크립트는 실제 사용자처럼 움직이게 한다.** 한 글자씩 입력, 실제 마우스 클릭·드래그, 여러 폭에서 위치·값까지 측정(#86·#149의 교훈). 화면 확인을 1280px 한 폭으로 끝내지 않는다.
- **AI 결과를 "통과"라고 적기 전에 무엇을 안 봤는지도 적는다.** 결과서·PR에 확인 범위와 확인 안 한 것을 같이 남기면 리뷰어가 빈 곳을 바로 본다.

## 6. 한 줄 소감
- 명세를 구체적으로 쓸수록 AI가 빠르고 정확해졌지만, AI가 놓친 버그는 결국 팀원의 리뷰와 검증이 찾아 주었다 — 다음에도 명세의 빈칸부터 채우고, AI 결과는 팀이 한 번 더 보는 흐름을 가져가고 싶다.
