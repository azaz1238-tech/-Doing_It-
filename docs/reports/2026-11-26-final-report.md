## 1. 요약

- **팀 협업 프로젝트 관리 서비스 '동잇'을 계획한 범위대로 완성하고 11/26 최종 발표를 마쳤다.** 프로젝트 단위로 업무를 등록하고 담당자·마감일·우선순위를 정해 칸반 보드로 관리한다. 차별화 기능은 업무 변경 이력과 마감 임박·지연 대시보드다.
- 범위: 필수(P0) 18개·2순위(P1) 10개 기능 모두 구현. 회의에서 예외로 정한 P2 3개(드래그 앤 드롭 1단계·달력·간트)도 넣었다.
- 품질: pytest 464개 통과, 수용 테스트 75개 모두 통과, 보안 점검 64개에서 남은 결함 0, 열린 이슈 0.
- 일정: M2(P0 게이트)·M3(기능 동결)·M4(발표)는 계획한 날에 마쳤다. M1(스펙 동결)만 3일 늦었고, 코딩 시작일은 지켰다(§3).
- 배포: https://doing-it.netlify.app (화면 Netlify, 서버·DB Railway). 발표 시연도 이 주소로 했다.

## 9. 회고 (요약)

상세는 [KPT 회고록](2026-11-26-kpt.md)에 있다.

- **Keep:** 명세를 구체적으로 먼저 쓰기(검사 순서·권한표·오류 코드까지), "명세 먼저" 규칙을 AI 지침에 넣기, 명세를 계약으로 써서 FE·BE가 서로 기다리지 않기, 상대 조가 명세로 검증하기
- **Problem:** AI가 놓친 것은 모두 경계·예외였다. 코드가 명세보다 먼저 들어간 변경이 있었다. AI가 쓴 문서를 검증 없이 믿은 적이 있었다.
- **Try:** 명세 틀에 "예외 입력·실패·빈 상태·문구" 칸을 두기, AI에게 극단값 테스트를 같이 요청하기, 명세 PR을 먼저 병합하기
